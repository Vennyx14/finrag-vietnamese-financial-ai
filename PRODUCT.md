# PRODUCT.md — FinRAG Product Specification

## 1. Product Identity

**Product Name**: FinRAG (Vietnamese Corporate Financial Research Assistant)  
**Target Repository**: `finrag-vietnamese-financial-ai`  
**Stage**: Phase 6 — Financial Research UI & Application Layer MVP  

## 2. Target Audience

1. **Financial Analysts & Equity Researchers**: Professionals needing quick, auditable extractions and calculations from official Vietnamese corporate financial statements (BCTC).
2. **Auditors & Compliance Officers**: Specialists requiring full lineage and provenance tracing from high-level ratios down to statutory accounting line codes (Mã số), tables, pages, and filing documents.
3. **Finance Students & Academic Researchers**: Researchers conducting reproducible quantitative analysis across Vietnamese listed enterprises.

## 3. Core Value Proposition

- **Zero Hallucination Guarantee**: Financial calculations are executed strictly with deterministic Python arithmetic—never generated by an LLM.
- **Auditable Provenance**: Every metric value is traced 1-to-1 to its source cell: `Ticker -> Fiscal Year -> Report Year -> Line Code -> Original Label -> Page -> Table ID -> Source Document`.
- **Independent Verification**: Every result undergoes independent post-reasoning audit checking numerical accuracy, formula alignment, period semantics, statement scope, unit compatibility, and provenance completeness.
- **Period Semantics Clarity**: Explicitly audits and communicates comparative columns (e.g. 2023 figures reported in 2024 annual reports) so users are never misled by filing year vs observation period differences.

## 4. User Experience Principles

1. **Evidence Before Decoration**: Visual styling exists to make financial figures and citations instantly understandable, not to entertain.
2. **Numbers Must Be Visually Legible**: Financial figures use tabular numerics (`font-variant-numeric: tabular-nums`) and provide both human-friendly formatted values (e.g. `₫62.85T`, `15.00%`) and full raw numbers (`62,848,794,351,367 VND`).
3. **Verification Status Must Be Obvious**: `VERIFIED`, `WARNING`, and `REJECTED` states are clearly labeled with plain-language explanations and individual check indicators.
4. **Honest Error Handling**: User input ambiguities, missing corporate disclosures, and verification rejections are clearly distinguished with actionable guidance.
5. **No AI Clichés**: FinRAG avoids generic chatbot conversational fluff, excessive card nesting, purple/blue glowing gradients, and unnecessary animations.
